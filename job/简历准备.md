2. 为什么无人机目标检测比普通目标检测更难？
小目标密集：小目标尺度较少，像素点少，特征信息不足，模型难以区分前景和后景，大量密集小目标也能会导致距离近的目标检测框误删除
尺度变化大：因为无人机的飞行高度和拍摄距离在不断变化

场景变化较多：无人机拍摄一般在户外，户外天气条件变化复杂，更考验模型的泛化性能

我做的这个项目是无人机跨场景目标检测，主要想解决两个问题：一是无人机图像里目标尺度差异特别大，二是雾天、夜间这类复杂场景会让检测性能掉得比较明显。

针对这个问题，我在 UAVDETR 的基础上，把 Decoder 里的 FFN 改成了一个动态 MoE 结构，里面有雾天、夜间、小目标和通用 4 个专家。模型会通过门控网络，根据当前 query 特征和场景信息，动态选择更合适的专家来处理不同样本。为了让专家真正学出分工，我还加了路由约束损失和负载均衡机制，避免所有样本都挤到少数专家上。

最后在 VisDrone 上，相比 baseline，整体 mAP 从 31.5 提升到 33.6，在复杂场景子集上的提升更明显。我主要负责的是整个方法设计、实验搭建和效果分析。

3. 为什么要做 MoE？
当前任务的目标是解决复杂场景下的无人机目标检测难的问题，主要面向的是常见的雾天、黑夜和小目标密集情况，这几种场景都有其特殊性
比如正常的晴朗白天，图像亮度较高，目标纹理特征清晰，边缘锋利，噪声较少，前景和后景区分度高
而雾天场景，因为一层雾的存在，导致，图像的亮度整体偏高，目标的纹理特征模糊，边缘不明显，有明显的噪声，前景和后景的难以区分
而黑夜场景，图像的整体亮度极低，部分亮，物体纹理缺失，边缘不明显，噪声极高，目标的特征信息较少
小目标区域，尺度较小，特征信息不足，前景目标和后景混杂在一起难以区分

从这几种情况看出，不同场景对于模型能力的要求不同，如果单




4. 为什么 MoE 放 FFN 不放 Attention？

因为Attention层做的时全局的注意力计算，是去寻找，样本的哪个位置是需要关注的，是最可能出现目标的位置，也就是在找位置，而FFN是在找到需要关注的位置后，对这些位置进行进一步的特征处理，而MOE本事是对不同的情况进行分类处理，在ATTention的全局计算中，无法进行分开进行，而FFN本事就是对不同的query进行处理，天然适合分类处理




5. 你的门控网络输入输出分别是什么？

输入的是带有全局分类信息的query编码
输出是归一化后的专家选择的概率值，
query 一般是 256 维，CLIP 的图片编码和文本编码维度相同，比如各 512 维，拼接后是 1024 维，再映射到 256 维和 query 融合，最后门控网络输出 4 个专家权重。




4. query 路由为什么不够？
只用 query 做路由不够，是因为 query 更偏局部目标信息，缺少全局场景信息。
尤其是夜间和雾天，有时候单个目标看起来都比较模糊，只靠局部 query 很难分清到底是雾天退化还是夜间退化。


5. 场景感知先验是怎么帮助路由的？

场景感知先验本质上是给门控网络加了一个全局环境提示。
这样门控网络做路由时，不再只依赖局部 query，而是把局部目标信息和全局场景信息结合起来。  
对我的任务来说，这样特别重要，因为雾天和夜间这种专家本身就是场景相关的，只靠局部特征容易分错，加了场景先验以后，路由会更稳定，专家分工也更清楚。


**局部特征相似，不代表最优处理方式相同。**  
目标检测虽然关注局部目标，但这个局部特征是在什么场景下形成的，会影响模型该怎么处理它。  
雾天和夜间都可能让目标看起来模糊，但雾天更偏低对比和平滑，夜间更偏低照、高噪和过曝，所以还是需要不同专家。


6. 为什么是 4 个专家？

雾天、夜间和小目标分别对应三种很典型的难点：
雾天是低对比和模糊，夜间是低照度和高噪声，小目标是目标本身像素太少。
另外再加一个通用专家，主要用来处理正常场景样本，或者一些不明显属于某一类的混合样本。


6. 感知路由交叉熵损失的作用是什么？

![](image/Pasted%20image%2020260420204447.png)
**感知路由交叉熵损失的作用，就是给门控网络一个额外的引导，让它更容易把样本分到更合适的专家。**  
因为如果只靠模型自己学，路由可能不稳定，或者很多样本都跑到同一个专家里。  
加了这个损失以后，门控网络在训练时会更倾向于学出比较清晰的专家分工，比如雾天样本更偏雾天专家，夜间样本更偏夜间专家。  
所以它的作用主要是**让路由更有方向、专家分工更明确**。
loss = -plog(p) ： 真实分布乘log预测，希望这个值越接近0越好，即预测值和真实值越接近越好

我这里的标签也是通过前置的多模态大模型得到的软标签




7. 负载均衡怎么设计，解决什么问题？
**负载均衡主要是为了防止专家使用不均。**  
因为在 MoE 里，如果不加约束，门控网络很容易把大部分样本都分给少数几个专家，其他专家几乎学不到东西，这样就会出现专家塌缩。  
我的做法是对各个专家被分配到的权重或样本占比加一个均衡约束，让不同专家都能分到一定训练信号。  
这样可以让专家利用率更高，分工更稳定，也能避免最后虽然有多个专家，但实际上只有一两个专家在起作用。

#### 1、整体架构讲解：
1、我这个项目主要解决的是无人机目标检测在复杂场景下性能下降的问题。相比常规自然场景，无人机图像里目标通常更小、尺度变化更大，而且雾天、夜间等退化环境会进一步破坏目标纹理和对比度，导致传统单一检测器的表征能力不足。  
基于这个问题，我在 UAVDETR 的基础上，把 Decoder 中的 FFN 重构为动态 MoE 层，设置了雾天、夜间、小目标和通用四类专家，通过门控网络根据 query 特征进行动态路由。同时，我引入了 CLIP 的全局视觉语义信息辅助路由决策，让模型不只依赖局部 query，还能感知整张图的场景条件。  
此外，我还设计了路由监督和专家负载均衡机制，缓解专家塌缩和路由不稳定问题。最终在 VisDrone 上，相比 baseline，mAP 从 31.5 提升到 34.6，在复杂场景子集上的提升更明显，说明方法对极端环境和尺度变化有更好的适应能力。

#### 2、MoE模块
##### 1、为什么想到用 MoE？
因为这个任务不是单一分布。无人机检测里同时存在天气退化、光照变化、目标尺度变化和小目标密集等问题。共享 FFN 对所有 query 使用同一套参数，更容易学成折中的平均表示；而 MoE 的好处是能让不同输入动态走不同专家，让模型容量更有针对性地服务不同子场景。



##### 2、为什么这个任务适合 MoE？


第一，**场景异质性强**，雾天、夜间、小目标和正常场景的统计分布差异明显。  
第二，**困难子集突出**，比如夜间和雾天本身更难，小目标更依赖特定表征能力。  
这类“多种困难模式并存”的任务，比较适合用专家分工去建模。

具体来说：
正常清晰的场景，对比度高，前后景区分明显，物体的纹理清晰，边缘锋利，噪声低，物体细节完整
黑夜场景：光照不足，亮度整体极暗，部分亮，物体纹理缺失，边缘断裂，噪声极高，目标几乎无细节
雾天场景：整体偏亮，对比度极低，前景和后景难以区分，噪声较低，目标的轮廓较为模糊
小目标场景：目标像素少，对比度低，纹理缺失，边缘模糊，容易与背景混淆，无细节信息

moe的合理性：
有用特征：
- **清晰场景**：纹理、边缘、色彩都可靠
- **雾天场景**：边缘和纹理被散射抹平，更依赖低对比度下的轮廓恢复
- **黑夜场景**：暗部信息丢失、噪声高、局部过曝，更依赖鲁棒亮暗结构和抗噪表征
- **小目标场景**：不是退化，而是目标本身可见信息极少，更依赖尺度敏感和局部微弱线索


同一个 FFN 要同时学会“纹理增强”“抗雾低对比恢复”“抗噪暗光适配”“小目标微弱结构放大”这几种变换，本身就存在参数竞争。

过程为：
1. 先用视觉编码器得到视觉编码v，
2. 在用一组场景prompt经过文件编码器得到文本原型t_k,
3. 根据图文相似度得到权重a_k，

###### 训练的模型配置：
- model: `ViT-B-32`

- weight decay: `0.1`
- epochs: `5` 到 `10`
- warmup: `500` 到 `2000` steps
- precision: `amp`
- optimizer: `AdamW`
- grad clip: `1.0`

#### 二、第一部分：场景分类怎么评

#### 1）先做数据划分
##### UAVDET处理：

从每个 sequence 里**按固定间隔抽帧**，
每个 sequence：

- **60% train**
- **10% gap**
- **30% test**
抽帧：
train：5
test：10
得到
训练集：9338  大概9000
测试集：2334  大概2000
 

gap和抽帧的原因：

gap：如果是train和tes连续的话，就会导致test的前几帧和train的后几帧会非常像，导致测试集不是真正未知的数据，会让测试结果偏高


抽帧：只看训练集的内部，数据会高度重复导致：1、样本冗余过多，有许多相同的无用图片，即训练的成本增加而收益很小，抽帧就是为了减少训练集内部的重复样本
也可能会让模型记住运动轨迹或者背景

### 2）定义场景标签体系

比如你最后统一成：

- foggy

- rainy

### 3）评估指标

最基础的是：

- **Accuracy**
- **Macro-F1**
- **每类 Precision / Recall**

所以最好加 **Macro-F1**，这样能体现少数类比如雾天、夜间的识别能力。

## 三、第二部分：下游检测增益怎么评

这才是“应用效果”的关键。  
不然你只是证明“分类准了”，还没证明“对检测有用”。

这里最标准的做法是做**对照实验**。

### 方案设计

你至少做两组：

**Baseline：**  
只用原始图像训练检测模型，不加场景信息。

**Ours：**  
把 Qwen2.5-VL 产出的场景标签或自动标注结果引入检测训练流程。

这个“引入”可以有几种方式：

#### 方式 A：把场景标签作为数据筛选或分组依据

比如：

- 针对雾天/夜间样本做单独重采样
- 对复杂天气样本提高采样权重
- 分场景训练或分场景调参

#### 方式 B：把场景标签作为模型输入先验

例如：

- 给检测模型增加场景 embedding
- 按场景切换专家分支
- 在 prompt 或 condition 中加入 scene token

#### 方式 C：用自动标注结果扩充训练数据

例如：

- 用 Qwen2.5-VL 补全缺失场景标签
- 生成统一描述，辅助清洗和对齐训练数据
- 生成伪标签，增强特定天气场景样本

你项目里最稳妥的说法通常是 A 或 C，因为最容易落地，也最容易讲清楚。

## 四、下游检测具体怎么做评估

### 1）固定检测模型和训练设置

要保证公平比较：

- 同一个检测模型，比如 YOLO / DETR / UAV-DETR
- 同一份 train/val/test 划分
- 同样的 epoch、batch size、学习率
- 同样的随机种子，或者多次跑取平均

不然面试官会问：  
“你这个提升到底是场景模块带来的，还是训练配置变了带来的？”

### 2）看哪些指标

最常用的是：

- **mAP**
- **mAP50 / mAP50-95**
- **按场景划分的子集 mAP**
- **按目标尺度划分的小目标 mAP**

因为你项目强调的是雾天、夜间，所以最关键的是：

- overall mAP
- fog/night subset mAP

你简历里那句“雾天与夜间子集 mAP 提升 4.2，整体 mAP 提升 3.1”，本质上就是这里来的。

### 3）实验表格长什么样

你最后最好有一个类似这样的表：

|方法|Overall mAP|Fog/Night mAP|
|---|---|---|
|Baseline detector|31.8|27.4|
|+ scene labels / auto annotation|34.9|31.6|

这样你就能很自然地说：

> 构建场景分类与下游检测增益评估流程，验证场景感知模块对复杂天气检测性能的实际收益。

## 六、如果你问的是“工程上怎么写出来”

那你可以按下面这个流程实施：

### Step 1：构建测试集

单独留一份场景标注完整的 test set，包含：

- 正常天气
- 雾天
- 夜间

### Step 2：跑场景分类评估

对 test set 做推理，统计：

- accuracy
- macro-f1
- confusion matrix

### Step 3：生成场景标签/自动标注结果

把 Qwen2.5-VL 的输出整理成结构化字段，比如：

{  
  "image": "xxx.jpg",  
  "scene": "foggy",  
  "objects": ["car", "bus", "pedestrian"]  
}

### Step 4：接入检测训练流程

把 `scene` 字段用于：

- 数据分层采样
- 样本加权
- 条件输入
- 数据清洗与筛选

### Step 5：训练检测模型

分别训练：

- baseline detector
- scene-enhanced detector

### Step 6：统计检测指标

输出：

- overall mAP
- fog/night subset mAP
- small-object mAP

### Step 7：做误差分析

比如：

- 雾天误检下降多少
- 夜间漏检下降多少
- 哪类目标受益最大

这样你的“评估流程”就完整了。
